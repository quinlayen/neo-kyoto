Keep briefings short: set the scene, list commands, state the goal. Do NOT teach concepts in briefings.

**Why:** The user felt briefings were too wordy and hand-holdy. TFWR teaches through mechanics, not text. The game should trust the player to figure things out.

**How to apply:**
- Briefings: ~15-25 lines max. Scene, commands, goal.
- Teaching goes in filesystem files (repair_protocol.txt, cheatsheets) that the player discovers through terminal exploration
- Error messages guide when the player makes mistakes
- Completion debriefs teach the NEXT concept (unlocked tool)
- Hidden files and permission-locked files create obstacles that reinforce previously learned skills
- Don't duplicate information between briefings and filesystem files
