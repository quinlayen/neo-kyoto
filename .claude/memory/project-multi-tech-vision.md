Neo-Kyoto interleaves technologies instead of front-loading all Python. The player learns basics, switches context, then returns with richer motivation.

**Current prototype (implemented): Python Phase 1 (C1-C4)**
- C1: Commands, print() → while True
- C2: While True, variables → if/else
- C3: If/else in loops → controlled while loops
- C4: Controlled while, counters, arguments → end of Python Phase 1

**Next phase (not yet built): Linux Terminal (C5-C6)**
- C5: ls, cd, pwd — navigate directory trees
- C6: cat, grep, pipes — read and search files
- Game fiction: "You need to connect directly to a system's terminal"
- Architecture: simulated filesystem, player types terminal commands

**Python Phase 2 + Linux Combined (C7-C8)**
- C7: for loops + lists — motivated by processing file listings / grep output
- C8: functions (def) — reusable automation across scripts
- Elevator and assembly contracts archived for reuse here

**Later phases:**
- SQL for city database queries
- Git for version control concepts
- Combined contracts requiring all technologies

**Why interleave:** For loops are more meaningful when you're iterating over real file lists. Functions are more meaningful when you're reusing logic across Python and terminal contexts. The multi-tech interleaving provides natural motivation for advanced Python concepts.

**How to apply:** Don't add for_loops or functions to the prototype. They come after Linux is introduced. Archived contracts (elevator, assembly) can be adapted for Python Phase 2 with Linux integration.
